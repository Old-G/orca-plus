# Ревью коммитов Codex по всем проектам

Скрипт `review.py` рядом, без модели Claude: сам находит новые коммиты и сам зовёт `codex review`. Нужен Codex CLI, вошедший в аккаунт (`codex login`).

- **Что смотрит:** проекты из `HQ/registry.yaml` (git, local); локальные ветки с коммитами за 3 дня; только коммиты владельца (`user.email` репо или глобальный), без merge. Перебазированная копия уже проверенного коммита (тот же patch-id) не проверяется второй раз.
- **Как:** раз в день в 18:30 `review.py daily` — один `codex review` на проект со списком всех его новых коммитов (до 40), «как одно изменение»: позднее исправление снимает раннее замечание; так тратится меньше лимита Codex. Упёрлись в лимит — остаток ждёт следующего вечера. Режим по одному коммиту остался: `review.py run --max N`.
- **Куда:** есть P0–P2 → один отчёт `HQ/updates/codex-review-<YYYY-MM-DDTHH-MM>.md` по всем проектам (Orca+ HQ → Reports + колокольчик). Чисто → строка в `~/Library/Logs/orca-plus-commit-review.log`.
- **Дальше:** Orca+ кладёт находки в журнал HQ+; правило в `HQ/routing.yaml` (с 19:00) открывает по проекту чат «Codex: починить» в новом worktree — он решает по каждой находке, чинит с тестом и закрывает её `orca hq settle`. P2 копятся. Что сделано — `orca hq route`, `orca hq thread <проект>/codex-fix-<дата>`.
- **Состояние:** `HQ/codex-review/state.json` (вне git): проверенные sha и patch-id, последние 500 ревью с уровнями.

Команды:
- `python3 "${CLAUDE_SKILL_DIR}/review.py" status` — сколько коммитов в очереди по проектам.
- `bash "${CLAUDE_SKILL_DIR}/run.sh"` — прогнать вечерний обход сейчас.
- `python3 "${CLAUDE_SKILL_DIR}/review.py" baseline` — пометить всё текущее проверенным (после долгого простоя, чтобы не жечь лимит на старое).

Ответ владельцу про найденное — по отчёту и журналу: проект, коммит, что не так, кто чинит.
